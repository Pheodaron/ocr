# Проверка первой версии — 2026-10-22

Проверено в управляемом Linux-окружении, Python 3.12.14; образ использует Python
3.12.15. Podman и mise здесь не установлены, поэтому контейнерная проверка
выполнена через Docker 28.4.0 / Docker Compose 2.40.3.

Успешно:

- `pytest -q`: **16 passed, 1 skipped**. Пропущен только явно включаемый тест
  настоящего OCR с подготовленными весами.
- Ruff lint/format, `node --check` и `git diff --check`.
- Разрешение `uv.lock` и установка CPU-зависимостей.
- Импорт PaddlePaddle 3.2.2, `is_compiled_with_cuda() == False`.
- Проверка конструктора PaddleOCR 3.3.2 с локальной конфигурацией без создания
  предикторов: имена и пути моделей сохраняются после объединения настроек.
- Сборка окончательного образа `localhost/document-ocr:0.1.0`.
- Импорт Paddle/OCR и чтение конфигурации внутри образа под UID 10001 с
  `--network none`.
- Валидация Compose и запуск API. Реальный HTTP-запрос с PDF получил 202.
  Клиент, локальная справка, OpenAPI и health доступны.
- Сохранение задания после перезапуска/пересоздания API с тем же томом.
- Доступность опубликованного `127.0.0.1:8000` с хоста.
- Явная ошибка worker при отсутствии весов без потери ожидающих заданий.

Ограничение проверки:

Официальный хост весов `paddle-model-ecology.bj.bcebos.com` заблокирован сетевой
политикой окружения: HTTPS CONNECT возвращает 403. Настоящие веса не загружены,
поэтому запуск полного OCR, качество русского текста/таблиц, RAM и время
распознавания **не подтверждены**. Тестовые результаты в обычных тестах создаёт
явно обозначенный тестовый движок, который не доступен как backend приложения.

Для завершения проверки нужно разрешить официальный хост или импортировать
подготовленные модели, затем выполнить:

```sh
OCR_RUN_MODEL_TESTS=1 uv run --frozen --extra ocr pytest -m ocr -v
```

Созданный для проверки Compose-проект `ocr-verify` и его тестовые тома удалены.
