# Мастерская обучения OCR

Отдельное локальное приложение подготовки данных и дообучения **LightOnOCR-3-0.8B** в каталоге `train-app/` репозитория `ocr`. Код существующего OCR-сервиса не изменяется.

Интерфейс: React и TypeScript. Сервер: Python, FastAPI, SQLite. Вычисления вынесены в независимые профили Podman Compose:

| Служба | Назначение |
| --- | --- |
| `app` | Проекты, документы, изображения, разметка, очередь, наборы данных и отчёты |
| `lighton4b` | Отдельная служба LightOnOCR-3-4B: предложения текста, таблиц и рамок |
| `qwen` | Обычный llama.cpp CUDA: Qwen3.8-27B UD-Q3_K_XL с mmproj, подключение по API |
| `trainer` | Дообучение 0.8B, оценка, пробное распознавание и экспорт GGUF |

Каждый следующий этап запускается пользователем. Запуск контейнера не запускает обработку проекта. Все вычислительные службы используют общую блокировку GPU; перед сменой модели остановите предыдущую службу.

## Требования

- Linux, Podman и поставщик Compose (`podman-compose` либо Docker Compose, работающий через Podman).
- NVIDIA RTX 5060 Ti 16 ГБ; установленный драйвер с поддержкой этой карты и CUDA 12.8.
- NVIDIA Container Toolkit с поддержкой CDI.
- `mise` и `uv`; Node.js нужен только для разработки или сборки интерфейса вне контейнера.
- Место для моделей, образов CUDA, исходных страниц и контрольных точек. Для подготовки окружения выделите не менее 50 ГБ свободного места сверх объёма документов.

Проверка доступа к GPU:

```bash
nvidia-smi
sudo nvidia-ctk cdi generate --output=/etc/cdi/nvidia.yaml
podman run --rm --device nvidia.com/gpu=all --security-opt label=disable \
  docker.io/nvidia/cuda:12.8.1-base-ubuntu24.04 nvidia-smi
```

## Подготовка

Все команды ниже выполняются из каталога `train-app`:

```bash
mise install
cp .env.example .env
mkdir -p data models
uv sync --frozen
```

При наличии интернета явно подготовьте модели. Скрипт разрешает выбранную ревизию в точный идентификатор и сохраняет SHA-256 локальных файлов:

```bash
uv run --with huggingface-hub python scripts/prepare_models.py lighton4b
uv run --with huggingface-hub python scripts/prepare_models.py qwen
uv run --with huggingface-hub python scripts/prepare_models.py lighton08
```

Для конкретного зафиксированного выпуска добавьте `--revision <SHA>`. Проверка уже скачанных файлов без сети:

```bash
uv run python scripts/prepare_models.py all --verify
```

Можно разместить собственные заранее скачанные файлы:

```text
models/
├── lighton4b/                  # Полный каталог Hugging Face, включая processor и tokenizer
├── lighton08/                  # Исходный LightOnOCR-3-0.8B в формате Hugging Face
└── qwen/
    ├── Qwen3.8-27B-UD-Q3_K_XL.gguf
    └── mmproj-F16.gguf
```

Рабочие службы не скачивают веса. Зависимости загружаются при сборке, модели — только отдельной командой подготовки. После подготовки окружения сеть вычислительных контейнеров изолирована от интернета.

## Запуск и переключение служб

Основное приложение работает без GPU и без запущенных моделей:

```bash
podman compose up -d --build app
```

Откройте **http://127.0.0.1:8001**. Если порт занят, измените `TRAIN_PORT` в `.env`.

Первый этап, LightOn-4B:

```bash
podman compose --profile lighton4b up -d --build lighton4b
podman compose --profile lighton4b logs -f lighton4b
```

После первого этапа можно открыть документы и исправить результат. Для второго этапа:

```bash
podman compose --profile lighton4b stop lighton4b
podman compose --profile qwen up -d --build qwen
podman compose --profile qwen logs -f qwen
```

Для обучения, оценки или применения контрольной точки:

```bash
podman compose --profile qwen stop qwen
podman compose --profile trainer up -d --build trainer
podman compose --profile trainer logs -f trainer
```

В интерфейсе нажмите **«Проверить службы»**. Перезапуск `app` при переключении не нужен. Если запущенная служба удерживает модель в видеопамяти, остановите её: отсутствие текущей генерации само по себе не освобождает GPU.

`lighton4b` и `trainer` используют один образ с разными независимыми процессами. Это разные службы и разные профили; они не встроены в основной сервер. Qwen имеет собственный образ llama.cpp. Сборка llama.cpp закреплена на `fa6769818708afd9807b22183ccda112fd563427` (`b10896`); CUDA-сборка предназначена для архитектуры SM120.

Контейнер Qwen по умолчанию использует один слот, контекст 8192 токена, Flash Attention, полное размещение слоёв и mmproj на GPU. Автоматическая подгонка размещения отключена. Вместимость проверяйте **на изображении**, а не только по успешной загрузке весов. В общий контекст входят изображение, инструкция и ответ; PDF передаётся постранично. Значение `QWEN_CONTEXT` задаётся в `.env`. Размер изображения автоматически ради вместимости не ухудшается.

## Работа в интерфейсе

1. Создайте проект и загрузите PDF, PNG или JPEG. Можно выбрать не менее 100 файлов за один раз; браузер передаёт их с ограниченным параллелизмом. Подготовка страниц продолжается после окончания загрузки.
2. Выберите документы и вручную запустите LightOn. Пустое выделение означает весь проект. Доступны режимы необработанных, ошибочных страниц и полного повторного распознавания.
3. При необходимости переключите службу и запустите Qwen. Отдельной кнопкой сравните сохранённые ответы. Совпадение не утверждает данные автоматически.
4. Откройте документ: слева изображение и рамки, справа результат. Выберите вариант модели, исправьте текст, таблицы или области. Вкладка «Таблицы» поддерживает строки, столбцы, объединения и разделение. Shift + нажатие второй ячейки задаёт прямоугольное выделение.
5. Утвердите текст и таблицы. Геометрия утверждается отдельно. Черновики сохраняются на сервер кнопкой; несохранённая правка сохраняется также в текущем сеансе браузера. При выборе другого ответа предыдущий черновик доступен отдельной кнопкой.
6. Назначьте документам выборки: обучение, валидация, тест. Задавайте одинаковое семейство похожим документам. Все страницы документа остаются вместе. Автоматическое распределение воспроизводимо, точные копии и заданные семейства не разделяются.
7. Создайте версию набора данных. Она включает только утверждённые редакции. Без проверки рамок страница доступна только обычному OCR. Экспорт содержит изображения, манифест и JSONL для каждой выборки.
8. Выберите версию и параметры обучения. Если назначены только обучение и тест, приложение создаст отдельную производную версию с валидацией примерно из 10% независимых групп обучающих документов; исходная версия не меняется. Для этого нужны хотя бы две независимые группы. Для продолжения укажите полную контрольную точку совместимого запуска. Конфигурация и версия данных должны совпадать.
9. Отдельно запустите тестовую оценку исходной и обученной модели. В отчёте доступны страницы, эталоны, ответы, CER, TEDS, TEDS-Struct, точные числовые ячейки и ошибки.
10. Для личной проверки загрузите новый документ, выберите страницу и контрольную точку на вкладке оценки. Без эталона приложение не придумывает числовой показатель качества.

Ошибка страницы не останавливает следующие. Кнопка остановки отменяет оставшуюся работу; во время обучения сначала завершается шаг и сохраняется контрольная точка. Аварийная остановка контейнера восстанавливается из последней целой точки. Неполные каталоги не отображаются как готовые модели.

Удаление задания распознавания не удаляет утверждённые данные. Завершённый обучающий запуск можно убрать из списка: минимальная история его данных сохраняется для контроля пересечения с тестом. Удаление всего проекта удаляет его документы, редакции и обученные модели.

## Дообучение и экспорт

Используются исходные веса LightOnOCR-3-0.8B, BF16, LoRA и накопление градиентов. По умолчанию визуальная часть заморожена; её адаптация включается явно. Уменьшения числа слоёв нет. Для смешанного обучения нужны утверждённые примеры `grounding`.

Перед первым шагом проверяется длинный пример; каждый последующий пример также проверяется без обрезки. Граница ответа определяется совпадением развёрнутого префикса штатного шаблона. Вход, изображение и выравнивание исключены из целей, ответ и завершающий токен включены. Координаты в `grounding` являются частью ответа и участвуют в обучении.

Валидация использует генерацию, а не только ошибку обучения. В смешанном режиме отдельно проверяется обычный OCR и доступная пространственная разметка. Контрольная точка содержит адаптер, состояние оптимизатора, положение в данных и состояния генераторов случайных чисел.

Экспорт объединяет адаптер с исходной моделью, сохраняет Hugging Face, создаёт F16 GGUF и соответствующий mmproj, затем Q4_K_M. При выбранном независимом тестовом наборе выполняется повторная оценка Q4 через llama.cpp на CPU. Если тест не выбран, экспорт не помечается как проверенный по качеству.

## Данные и резервная копия

```text
data/
├── workbench.sqlite            # Метаданные и очередь
├── projects/<id>/
│   ├── sources/                # Исходные документы
│   ├── images/                 # Изображения страниц без потерь
│   ├── raw/                    # Исходные ответы моделей
│   ├── datasets/               # Неизменяемые версии данных
│   └── runs/                   # Обучение, контрольные точки, оценки, экспорт
├── compute/                    # Устойчивые операции вычислительных служб
└── gpu.lock                    # Исключительное использование GPU
```

В управлении проектом есть скачивание резервной копии. Перед копированием завершите или отмените задания проекта. База снимается штатным механизмом SQLite с учётом WAL; файлы проверяются по SHA-256. Восстановление доступно на стартовом экране. Совпадающий идентификатор проекта отклоняется, слияние редакций не выполняется. Исходные модели в резервную копию проекта не включаются.

## Разработка и проверки

```bash
mise run install
mise run dev
```

В другом терминале:

```bash
mise run frontend
```

Интерфейс разработки: http://127.0.0.1:5173, API: http://127.0.0.1:8001, документация API: `/docs`.

```bash
mise run check
cd frontend
CHROMIUM_PATH=/usr/bin/chromium npm exec playwright -- test
```

Браузерная проверка использует отдельный временный проект и явную подмену вычислений из `tests/`. Она проверяет интерфейс и обмен данными, не качество моделей. Подмена не входит в рабочие контейнеры.

Для GPU после сборки дополнительно проверьте PyTorch:

```bash
podman compose --profile trainer exec trainer python3 -c \
  'import torch; print(torch.cuda.get_device_name()); print(torch.ones(2, device="cuda") * 2)'
```

## Диагностика

```bash
podman compose ps
podman compose logs -f app
podman compose --profile lighton4b logs -f lighton4b
podman compose --profile qwen logs -f qwen
podman compose --profile trainer logs -f trainer
```

У некоторых выпусков `podman-compose` команда `ps -a` не поддерживается; используйте `ps`. Профиль указывайте также в `logs`, `exec` и `stop`.

Подробности вычислительных операций сохраняются в `data/compute/<служба>/<операция>/`: `status.json`, `progress.json`, `log.txt`, `result.json`. Частично сохранённая контрольная точка имеет суффикс `.writing` и не считается готовой.

При проблемах TLS задавайте доверенный сертификат прокси (`SSL_CERT_FILE`, для npm — `NODE_EXTRA_CA_CERTS`). Проверку TLS не отключайте. Containerfile поддерживает необязательный секрет сборки `proxy_ca` с доверенным набором сертификатов.
