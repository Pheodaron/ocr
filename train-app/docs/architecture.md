# Устройство приложения

## Границы служб

`app` — единственный владелец основной SQLite. Он хранит проекты и очередь, раздаёт интерфейс и вызывает вычислительные HTTP API. Процессы моделей не подключаются к его базе.

`lighton4b` — собственный процесс FastAPI, загружающий LightOnOCR-3-4B по запросу и сохраняющий модель между страницами. `trainer` — другой процесс того же образа; каждая тяжёлая операция выполняется дочерним процессом, чтобы память модели и оптимизатора освобождалась после завершения. `qwen` — стандартный llama-server CUDA без обязательного дополнительного сервера Python.

Общая локальная блокировка `data/gpu.lock` получается до загрузки модели и удерживается всё время её пребывания в GPU. У Qwen это `flock --no-fork`; у Python-служб — `fcntl.flock`. При смерти процесса ядро освобождает блокировку. Блокировка не освобождается по одному лишь тайм-ауту HTTP.

## Редакции

Ответ модели неизменяем. Каждое сохранение человеком создаёт `Annotation` с родителем и ссылкой на исходное изображение. `Page.current_annotation_id` выбирает текущую редакцию. Клиент передаёт ожидаемый идентификатор: если другой запрос уже сохранил новую редакцию, сервер возвращает 409 вместо перезаписи.

Каноническая расшифровка собирается из упорядоченных фрагментов. Полный текст запроса обязан совпадать с ней. Геометрические рамки необязательны для текста, но обязательны для экспорта `grounding`. Интерфейс снимает утверждение геометрии после изменения рамок; изменение содержимого или порядка снимает оба утверждения.

Версия данных хранит содержимое утверждённых редакций и SHA изображений, а не ссылку «всегда брать последнюю». Изменение страницы не меняет запущенное обучение.

## Очередь и остановка

Отдельный цикл готовит документы на CPU; другой выполняет вычисления. Выполняется один диспетчер, что проверяется локальной блокировкой. Каждое массовое задание состоит из независимых операций страниц. Ошибка записывается в операцию, затем берётся следующая.

Python-службы принимают устойчивый идентификатор операции. Повтор с тем же содержимым возвращает существующую операцию; другое содержимое под тем же идентификатором отклоняется. Состояние и результат сохраняются до ответа основному приложению.

Запрос операции фиксируется до первого отправления и повторно используется после восстановления связи. Внутри вычислительной службы очередь в памяти пополняется из файлов журнала при запуске; опрос не перебирает все завершённые операции каждые полсекунды. За один проход диспетчер проверяет каждую службу не более одного раза независимо от числа ожидающих заданий.

llama.cpp не предоставляет такой долговечный протокол. Основной сервер ведёт задание Qwen сам и использует один слот. После потери соединения новый запрос не отправляется, пока слот занят. Потерянную генерацию можно повторить после подтверждённого освобождения; уже сохранённые страницы не повторяются.

В обучении остановка обрабатывается на границе шага оптимизатора, затем сохраняются адаптер и состояние продолжения. Полностью записанный каталог публикуется с `complete.json`. Авария может потерять шаги после последнего сохранения; интерфейс обнаруживает только завершённые контрольные точки.

## Сравнение

Версия алгоритма — `ordered-dp-1`: таблицы и строки сопоставляются динамическим программированием с сохранением порядка и явными пропусками. Ячейки сравниваются по структурному месту после выравнивания строк; поиск совпадающего числа по всей странице запрещён. Переставленные таблицы и разделение одной таблицы на две штрафуются как структурные расхождения.

TEDS вычисляется деревом `table → tr → td`, с объединениями и нормализованным видимым содержимым. Заголовки `th` приводятся к совместимой структуре оценщика. Пропущенная таблица имеет нулевой показатель. Числовой показатель охватывает ячейки с любой цифрой, включая даты, коды и значения с единицами измерения; сравнивается полное содержимое ячейки. Пропуски остаются в знаменателе; ведущие нули, знак и десятичная запятая сохраняются.

## Интерфейс

`App` связывает проекты и основные разделы. Отдельные компоненты отвечают за документы, наборы, обучение, очередь, просмотр страницы, геометрию и таблицы. Запросы находятся в `api.ts` и `hooks.ts`; строгие типы — в `types.ts`.

`tableModel.ts` содержит чистые операции над сеткой объединённых ячеек. Он отделён от React и проверяется без браузерной разметки приложения. При правке текст остаётся строкой. Просмотр очищает опасный HTML, но не перезаписывает этой копией обучающий ответ. Исходная разметка хранится отдельно.

Данные GPU-зависимостей не входят в основной образ. Все зависимости фиксируются `uv.lock` и `package-lock.json`. Модели готовятся явно; рабочие службы используют только локальные файлы.
